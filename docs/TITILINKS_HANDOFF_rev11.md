## LESSONS ON RECORD (rev 10→11)
- **Verify runner semantics before asserting them.** Two JWT bricks were wrong because Playwright doesn't run projects in config order; the fix was launching two halves. Read the tool's docs, then write the brick.
- **The gateway can rewrite your headers.** Supabase serves edge GETs as `text/plain`; Vercel's header override on the rewrite fixed it. Probe live headers after every deploy, don't infer them.
- **When a brick changes what a route serves, grep the specs for that route before committing.** PRERENDER.1 made spec 73's "/templates has no summary" assertion stale; it was caught only after deploy. One `grep -n "/templates" tests/*.spec.ts` in the spec would have caught it.
- **Don't confuse the process.** The handoff is for the architect; CC gets bricks. Implying otherwise cost a full cycle of frustration.
- **A stale paste is a stale paste.** Say so in one line instead of re-explaining the last step.
- **Check numbers you're about to publish.** The llms.txt pricing line and a Vercel IP were both wrong on first draft; `pricing.ts` and the Vercel domains screen were the truth.
- **CC's judgment is an asset when the spec invites it.** Ask for departures-with-reasons; review them; accept the good ones. Six of six on META.1, five of five on PRERENDER.1.
- **Spec what CC needs, not everything you know.** Joey noticed the prompts getting long; the research behind them is the point, the prose isn't.
- **Plain words to Joey.** He said so directly on Sep 24. Two paragraphs above a prompt should be readable by someone who has never opened the repo.
- Still #1: read the feature's intent before calling it a defect; measure before theorising; one CC session; launch long runs outside Claude Code.
